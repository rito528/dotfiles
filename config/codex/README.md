# Codex のタスク確認フック

試用として、Home Manager は Codex のグローバル設定に 3 つのフックを登録します。ユーザーの入力を記録し、質問ツールの呼び出し前と応答の終了前にタスクの状況を確認します。すべてのプロジェクトに適用されます。

Home Manager が管理するこの3つのフックは、定義に対応する信頼済みの値も一緒に配備します。反映のたびに `/hooks` で1件ずつ信頼する操作は不要です。更新でNix storeのパスが変わった場合も、新しい定義から信頼値を生成します。対象外のフックは通常の確認が必要です。この変更を作成しただけでは `home-manager switch` は実行されません。

終了の判定では、会話全体で求められた成果と、実際にできたことを比較します。資料や方向性を示して具体的に作成したいと伝えた依頼は、相談調の表現でも作業の依頼として扱います。既存の依頼とのずれを質問で指摘された場合も、説明だけで修正を終えたことにはしません。説明や比較だけの依頼、一般的な能力の質問、将来の構想とは区別します。

質問と終了の確認では、通常の Codex 認証を使って OpenAI の Codex モデルを追加で呼び出します。別の一時ディレクトリで一時的なセッションを起動し、ツールと親のフックを無効にします。追加の通信と利用量が発生します。各ターンで同じ種類の確認による拒否は最大 1 回で、`request_user_input` と `request_user_input_async` は同じ上限を共有します。判定できない場合やエラー、タイムアウト時は通過させます。会話履歴の読み取りは一部の形式に限られ、読み取れない場合も通過します。この試用による改善はまだ実証されていません。

デフォルトモデルと確認フックの判定モデルは `gpt-6.2-sol`、推論量はmediumです。判定モデルは専用の静的モデル定義にも指定しているため、更新時には `task_check.py` と `judge_models.json` の両方を変更してください。

状態は `${XDG_STATE_HOME:-~/.local/state}/codex-task-check` に保存します。ディレクトリの権限は `0700`、ファイルは `0600` です。ユーザー入力の原文を合計64,000文字まで保存し、判定結果の種類・所要時間・差し戻し回数も記録します。履歴全体や判定プロセスの出力を複製して保存することはありません。最終更新から7日を過ぎた会話の状態は、次にフックが起動したときに削除します。定期的な削除は行いません。

判定に送る内容は、現在の会話のユーザー入力、質問または終了文、直近のアシスタント発言とツールの呼び出し・結果です。推論の内部記録やsystem/developerメッセージは除きます。送信先は通常の認証を使うOpenAIで、別のプロバイダーにはフォールバックしません。新しい会話での試用を想定しており、入力の履歴が欠けている場合や容量の上限を超えた場合は差し戻しません。`codex exec --ephemeral` など、履歴を保存しない実行も対象外です。

`codex-task-check` の `--mode` は `enforce`、`observe`、`off` を指定できます。設定を変える場合は `modules/codex.nix` のフックコマンドを変更してHome Managerを反映します。`/hooks` では内容の確認や一時的な無効化ができますが、次のHome Manager反映時には管理対象の設定に戻ります。

信頼値は、Codexが `/hooks` で保存する `hooks.state` と同じ形式です。[公式の信頼確認の説明](https://learn.chatgpt.com/docs/hooks#review-and-trust-hooks)と[ハッシュ生成の実装](https://github.com/openai/codex/blob/rust-v0.169.0/codex-rs/hooks/src/engine/discovery.rs#L972)を基に、対象3件の定義から生成しています。将来のCodexでハッシュ形式が変わる可能性があるため、更新時は次の実CLI検証を通してください。

## 検証

通常のテストは `python3 -B -m unittest discover -s tests/codex-task-check -v` で実行します。`CODEX_TASK_CHECK_CODEX` にCodex実行ファイルの絶対パスを指定すると、ローカルの固定応答サーバーを使い、実際のフック経由で質問と終了を差し戻せること、判定担当にツールが渡らないこと、未登録のコマンド・編集要求が実行されないことも確認します。専用のCIワークフローでも実行します。

さらに `CODEX_TASK_CHECK_ACTIVATION` にHome Managerのビルド結果の `result/activate` を指定すると、生成された信頼値を実際のCodexの `hooks/list` で確認します。対象3件が信頼済みになり、変更された定義や追加のフックは信頼されないことを検証します。ユーザーの設定を書き換えたり、フックやモデルを実行したりはしません。

実モデルの合成評価は `python3 tests/codex-task-check/evaluate.py --output /tmp/task-check-evaluation.json` で明示的に実行します。追加のモデル利用が発生するため、通常のテストやCIには含めません。実行前に固定した期待値と、失敗・タイムアウトを含む結果を比較します。合成ケースの成功だけで実際の会話での改善率を判断することはできません。

ツールの無効化は専用の静的モデル定義とCodexの機能設定を組み合わせています。Codex更新時には上記の実行ファイルを使うテストを通してください。任意のsystem/managed設定を持つ環境への適用は未確認です。通常の文章による質問や、実行障害による停止後の自動復旧は、このフックの対象外です。

2026年11月18日の合成評価では、`gpt-6.1-sol`・推論量mediumで10件すべてが期待値と一致しました。差し戻し2件、通過7件、判定不能1件で、1件あたり約16〜23秒でした。実行失敗とタイムアウトはありませんでした。これは公開可能な例を使った1回の評価で、実際の会話での改善率を測った結果ではありません。

同日の追加検証では、具体的な作成意図を示した依頼にも構成案だけ返して終了する例を、旧判定が通すことを再現しました。判定を修正し、相談調の依頼や訂正の質問、実装を求めていない質問などを加えた18種類は、すべて期待値と一致しました。1件あたり約15〜21秒で、実行失敗とタイムアウトはありませんでした。

同日、判定モデルを `gpt-6.2-sol`・推論量mediumに更新し、同じ18種類を再評価したところ、すべて期待値と一致しました。1件あたり約15〜27秒で、実行失敗とタイムアウトはありませんでした。これは合成ケースでの確認であり、実際の会話での改善率は未確認です。
